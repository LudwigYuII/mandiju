# 第二阶段：叩扉

本轮以现有 Next.js 15 / React 19 / libSQL / R2 实现书斋、拜帖与赠答；账号、雅号、邀请、历史笔友和信件继续沿用。

## 行为与页面

- 原 `/study/[pen]` 继续可用；门庭展示书斋名、公开小序、原已公开尺牍、印章、闭关和双向同意的引荐人。书斋名可留空，填写时二至二十字、可重名。
- `/study/edit` 分别编辑公开小序（五百字）和内斋札记（五千字）。默认空白，不从旧信、草稿自动回填内容。内斋只供主人及单向获准访客阅读；服务端用带授权条件的查询读取，不把内斋文本传给无权浏览者或公共缓存。
- `/visits` 私人管理拜帖、赠答和屏蔽，分批分页，无公开数量、访客记录或在线状态。设置和全站导航提供入口。
- 拜帖附一至一百字。可接见、婉谢、收回；主人随时撤回内斋访问。婉谢、收回、撤回后冷却三十日，主人可主动允许重新递交。既有笔友不自动获得内斋授权，接见不改变笔友或寄信权限。
- 赠答四种固定小物：一枝梅、一盏茶、一片雪、一枚落叶；附言最多一百字、可空。仅沿用现有可通信关系，双方私密；收件人可收下、婉谢或关闭赠答。寄件人只见“已赠出/暂存中”，不显示对方收下、婉谢或阅读状态。
- 拜帖和赠答各限每人每日五次，赠答同对象每日一次；按公共时区分日，内部计数不公开。另对操作请求限每分钟六十次。成功赠送有幂等键，资料有修订号，拜帖状态有条件更新。
- 闭关时新赠答暂存至出关；延长/提前出关会同步调整尚未开放赠答。普通信件继续原有送达规则。
- 屏蔽双向禁止新拜帖、赠答、笔友申请和寄信；撤销双方现有内斋授权。普通批注也检查与作者的屏蔽关系。已送达信保留；在途信保存原时间并暂存，解除双方全部屏蔽后按原定时间与收件人当前闭关时间中较晚者恢复。屏蔽期间闭关操作不能意外开放暂存信。解除屏蔽不恢复旧内斋权限。

## 增量迁移与回退

schema_migrations 版本3增加 study_profiles、study_visits、user_blocks、study_events、gifts，以及 letters.blocked_deliver_at。无删表、删列、历史内容公开或旧关系转换。反骚扰事件账本仅保留最近三十五日；备份沿用原有加密快照策略，备份到期前可能保留更早快照。

发布前在当前已审查分支运行 backup 工作流的 migrate 操作：完整导出、隔离恢复、加密并成功上传后才执行 upgrade-schema.cjs。此操作不再次迁移或删除旧图片；retire 路径保留原单对象限制。本轮不运行 retire。

先增量迁移，再合并发布。低数据量下无需专门停机，写事务可能短暂排队。应用回退保留新结构；启用屏蔽后不得回退到绕过屏蔽、把暂存信当普通时间重算的旧代码。紧急时关闭新入口并前向修复权限逻辑。

## 修改范围、成本与验证

主要新增 study-policy/service/actions、StudyForm、书斋编辑及拜帖赠答管理页；扩展原书斋、导航、设置、信件权限/笔友/闭关、迁移、简繁字典、备份工作流及更新日志。

只有短文本和固定小物，无新上传、新付费服务、库存或交易；成本为少量数据库存储和原有请求流量。未新增外部通知渠道；赠答在站内管理页查看，拜帖通知只提示有帖，不含附言正文。

必要检查包括类型与生产构建、真实隔离数据库状态转换/越权/幂等/限流/双向屏蔽，以及匿名/无权/获准/撤回后的实际路由响应与真实资料表单提交。沿用现有备份恢复检查；不重复无关的全站检查。

人工体验顺序：设置里“布置书斋”题斋名与小序；另一个账号递帖，主人接见后进入内斋；撤回后刷新旧链接应不可读；原笔友间赠一盏茶并婉谢；设置闭关和屏蔽后检查暂存及解除。简繁界面只转换界面文案，不改用户原文。

## 边界

尚未加入作品编辑系统、私信公开授权、题跋收录、自由拖动陈设、第三阶段唱和或雅集。内斋目前陈列主人自己填写的一篇札记，不冒充完整作品管理系统。

旧公开图片源对象撤除属前轮工作；本轮未获 CDN 精确清理权限，不声称缓存已清理。相关清理路径见 phase-two-plan.md。
