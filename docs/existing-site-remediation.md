# 现有网站四批整改及上线说明

本次在原有 Next.js、libSQL、账号、邀请与信件结构上整改。所有改动先在独立分支交付，尚未修改生产数据或配置。它们不包括后续54项功能的整体开发。

## 改动范围

1. 统一私人信件的服务端访问规则，修复送达前详情、打印、回信引用、设置页信匣和主题列表中的信息暴露；草稿保存增加所有权及修订号检查。
2. 注册原子占用邀请码；发信增加事务与幂等键；通知使用持久任务、通道唯一键、租约及失败重试；增加独立 Cron 鉴权、会话版本及原子限流。新图片解码、清理元数据、压缩后保存，私人附件使用独立私有存储与鉴权读取。备份在一致读事务中导出，并收集附件后加密上传，提供隔离恢复工具。
3. 停用每日积分、寄信扣费、数量成就和刷信发邀请码；移除公开互动计数及对方阅读状态；公开必须明确选择并确认。旧邮票归属、邀请、用户与信件不删除。荐帖暂由站主管理发放。邮件提醒默认关闭、可自愿开启，通知不带私信标题或正文。
4. 首页改为书案入口，公开信阅读移到 `/letters`，保留分页；统一纸墨配色、减少毛玻璃与装饰。界面使用简繁词典，作品原文不转换，切换不刷新页面；提供繁体字形字体。原生日不强制改写，用户可改为只填写月日。历法按年份计算，日期按明确公共时区处理。信封用原生 details/summary，可键盘操作，正文不依赖动画或观察器才出现。

旧阅后即焚信继续按原约定处理，不再新建。寄件人不再得知对方拆封或焚毁状态。旧时光胶囊的送达时间保持不变；新自寄未来信最多一年。好友、通信册、既有公开作品、书房、头像及已收藏邮票继续保留。

## 兼容性和迁移

`lib/schema-upgrades.ts` 的版本1迁移使用写事务与迁移台账，增加：

- users：会话版本、邮件通知偏好。
- letters：发信幂等键、撤下公开展示标记；不回填或重算历史送达时间。
- drafts：修订号；notifications：可为空的唯一事件键。
- media、letter_media：附件归属与关联；保留历史公开地址迁移记录。
- delivery_jobs：通知任务、租约、重试与通道状态。
- admin_audit、schema_migrations：治理操作和迁移记录。

旧积分、点赞、成就和收藏表保留，停止使用不等于删除数据。后台原来的“删除”改为只撤下公开内容并审计，不硬删除私信。已有公开信仍维持原来访客可读范围；没有把任何旧私信改为公开。

旧代码的初始建表路径仍保留以兼容既有部署；补列有并发容错、失败初始化允许重试。新迁移可以提前单独运行。后续可以继续将旧初始化完全移出请求路径，本次没有大规模替换数据库层。

## 合并上线前必须配置

- `MDJ_SECRET`：至少32字符的随机签名密钥。缺失或过短时生产请求拒绝不安全运行。重置密码后旧会话失效。已有短密码仍可登录，新设密码至少12字符。
- `CRON_SECRET`：独立随机密钥；Vercel环境与GitHub Actions Secret须一致。伪造 User-Agent 不再被接受。
- `MDJ_SITE_TIME_ZONE`：默认 `Asia/Shanghai`，即初始公共时间 UTC+08:00。日期选择按此公共时区解释，不能依赖服务器本地时区。修改公共时区后需重新构建部署，以保持客户端预览与服务端一致。
- 使用R2时，保留原公开 `R2_BUCKET`，额外设置真正关闭公共访问的 `R2_PRIVATE_BUCKET`；名称须不同。现有R2访问凭据需要有两个桶的相应权限。
- 生产环境没有R2时，必须提供持久、非公开的 `MDJ_PRIVATE_STORAGE` 目录。Vercel临时文件系统不适合作为永久附件存储。
- GitHub备份需要数据库凭据、附件存储凭据及 `MDJ_BACKUP_RECIPIENT_CERT`。该项只保存加密用的公钥证书，私钥留在站主本地，不能上传CI或提交仓库。
- 可配置 GitHub Repository Variable `MDJ_SITE_URL` 为正式HTTPS站点地址，启用每10分钟的送达扫描；GitHub定时任务是尽力调度，不承诺精确到秒。信件可读性仍由服务端送达时间决定，通知通道独立重试。原有Vercel每日Cron作为另一入口保留。

客户端新文字默认不会因界面简繁切换而改变，保留输入和阅读位置。TC字体按字体使用及unicode子集加载，避免将全字库一次下载到每个用户设备。

## 首次安全上线顺序

1. 核对生产实际提交、数据库地址与R2配置，暂停新写入进行迁移窗口；先完成受保护的整库和附件备份，并在隔离目标恢复验证。不要把明文备份上传公开仓库。
2. 配好密钥、私有桶、备份证书及相关凭据，在预发布环境运行版本1迁移：

```sh
node --require tsx/cjs tools/upgrade-schema.cjs
```

3. 检查历史附件迁移计划，默认只读：

```sh
node --require tsx/cjs tools/migrate-private-media.cjs
```

确认备份可恢复后应用迁移。脚本先创建私有副本并更新关联；只有明确提供退休参数才撤销不再被任何内容引用的旧公开副本：

```sh
node --require tsx/cjs tools/migrate-private-media.cjs --apply --backup-verified
node --require tsx/cjs tools/migrate-private-media.cjs --apply --backup-verified --retire-public
```

**只更新数据库或页面链接不能使旧公开地址失效。** 需要同时确认源桶、旧域名/CDN缓存和历史部署中的副本已撤销。被公开头像等继续引用的共享文件会保留并报告，须单独处理。无法识别的外部历史图片不会被自动抓取或删除。

4. 上线新代码并逐项检查权限、草稿、发信、旧收藏、未到期胶囊和通知。邮箱、Web Push服务实际连通性要在真实配置后单独验收，隔离测试没有发送真实邮件。
5. 手动执行首次加密备份，确认成功、可解密及数据库和附件可恢复，再恢复正常写入。不要把“工作流存在”当成“备份有效”。

## 加密备份与恢复

站主在自己的可信设备生成证书和私钥，给私钥设置口令并离线保管，例如：

```sh
openssl req -x509 -newkey rsa:3072 -keyout backup-private.pem -out backup-recipient.pem -subj "/CN=mandiju-backup" -days 3650
```

只将 `backup-recipient.pem` 的内容作为CI的证书配置。新备份附件只有 `backup.p7m` 和密文校验值，公开仓库不再上传明文JSON。缺少必要配置或有附件无法备份时，任务失败并不生成“完整备份成功”的假象。

在可信设备解密后，使用全新隔离数据库进行恢复；工具拒绝覆盖非空数据库或等于源地址的目标：

```sh
openssl cms -decrypt -binary -inform DER -in backup.p7m -recip backup-recipient.pem -inkey backup-private.pem -out snapshot.tar.gz
# 在受保护目录解包，找到含manifest.json的快照目录。
node tools/restore-backup.mjs /path/to/snapshot
node --require tsx/cjs tools/restore-media-backup.cjs /path/to/snapshot
```

第一条恢复命令使用 `MDJ_RESTORE_DB` 和可选 `MDJ_RESTORE_AUTH_TOKEN`；附件恢复使用指向隔离恢复库的 `MDJ_DB`，以及恢复目标的私有存储配置。新附件恢复到原对象键，旧公开图片恢复为私人附件，不写回公开uploads。

当前可见的3次历史backup运行全部失败且无附件；最近一次在Secrets检查失败。没有在这些运行中发现已上传的明文备份，也不能据此证明生产有其他可用备份。

## 验证和限制

- `pnpm typecheck`、`pnpm test`、`pnpm build`。
- `node tools/verify-local.cjs`：启动隔离的生产服务器，运行实际HTTP边界测试，导出并恢复匿名数据库和附件，验证加密归档解密后逐字节一致。
- `.github/workflows/verify.yml`在PR中重复上述检查；不读取生产凭据。
- 依赖保留Next.js 15路线并升级维护版本，修复图片处理及PostCSS依赖问题；锁文件随代码提交。
- 本环境的Chromium因Unix socket限制不能启动，浏览器截图与真实移动端视觉检查尚未完成。不要把HTML/API测试说成完整视觉或屏幕阅读器验收。可选 `--screenshots` 需要可运行的Playwright/Chromium环境。
- 邮件服务使用事件幂等键，站内通知有数据库唯一事件键；推送重试用相同标签折叠展示。外部通道不能承诺跨任意崩溃和第三方故障的绝对“恰好一次”。

## 回退

先备份并停止写入，再回退应用提交。新增结构保留，不运行删除旧内容的down migration。已迁移的私人附件不能为了回退而重新公开；旧应用不认识新附件URL时应保留新媒体读取服务或先修兼容层。不要把回退旧公开访问漏洞当成合格回滚。版本化迁移、数据核验、私有存储及恢复步骤需要在预发布环境先演练。

新增界面文案时同步维护 data/ui.zh-Hans.json 和 data/ui.zh-Hant.json。词典只用于显式标记的界面文案，不得将用户原文传入自动转换流程。
