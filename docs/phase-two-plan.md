## 1. 已有能力与缺口

- app/study/[pen]/page.tsx 已按当前雅号展示个人页、公开且已送达的信件、印章、闭关及双向同意的引荐人。复用此路由，内部关联使用用户ID。
- lib/friends.ts 和 lib/actions.ts 已有笔友申请、接受、拒绝、解除及寄信权限；它们不是内斋访问授权。原有笔友不得自动升级为内斋访客。
- lib/access.ts / lib/letter-policy.ts 已控制信件访问；进入内斋不赋予查看主人私信或草稿的权利。
- 当前 schema 未见书斋资料、拜帖、赠答或用户间屏蔽表；现有 banned 是账号停用，不能充当个人屏蔽。
- 迁移沿用 lib/schema-upgrades.ts；增量版本号实施时以最新主分支为准，当前下一版本为3。

## 2. 建议规则（实施方案，非已上线行为）

| 功能 | 建议规则 |
|---|---|
| 门庭 | 沿用现有公开页；仅展示雅号、私印、书斋名、主动发布的门庭介绍及既有公开内容。介绍默认空白。无浏览量、访客名单或最后在线时间。 |
| 内斋 | 默认仅主人；主人批准的访客可访问。第一批仅提供主人明确发布的内斋札记，不复制或自动纳入任何历史私信、草稿。门庭与内斋分别编辑，保存前显示可见范围。 |
| 书斋命名 | 可重名；建议2–20个字符，纯文本。公共和内斋介绍分别建议最多500字。内斋札记先用纯文本，最多5000字，不新增上传。 |
| 拜帖 | 登录并题号后可递一句话（建议1–100字）；一次只保留一份待处理申请。接见授予单向访问，婉谢不公开理由或次数。可撤回待处理拜帖。 |
| 再次递帖 | 待处理时不可重复；婉谢或撤回访问后建议30天内不可重递。主人可主动重新开放；解除屏蔽不自动恢复权限。 |
| 撤回访问 | 主人随时撤回；每次页面和数据读取重新查授权，不以旧链接或缓存维持访问。撤回不解除笔友，也不删除往来信。 |
| 屏蔽 | 双向阻止新的拜帖、赠答与寄信，立即撤销相互内斋权限；不删除历史信件。已在途信件先冻结新通知与接收方开放，解除后依原定时间恢复；需与闭关/投递事务一起实现，避免只拦前端。 |
| 赠答 | 第二批接入；四种固定小物：梅、茶、雪、落叶。仅既有可通信关系可赠送，附言可空、最多100字。独立于普通信件，不改变信件延迟或催回复。 |
| 赠答隐私 | 默认仅双方可见；收件人可拒收、关闭全部赠答或屏蔽来者。首版不提供公开陈列，不显示累计数量、价值或稀有度。 |
| 频率 | 建议拜帖每人每天最多5次，同对象重复受冷却限制；赠答每人每天最多5次、同对象每天最多1次。只作后台防骚扰限制；日期按网站公共时区计算，存储为UTC。 |
| 闭关 | 允许浏览已授权空间；不新增催办通知。赠答沿用来信暂存原则，出关后开放。拜帖可暂存供主人自行处理。 |

以上数值为建议默认值，可配置；需求书没有规定这些具体数字。
涉及私信公开的双向授权、作品系统、题跋收录与自由陈设留给后续任务；本阶段保留扩展位置，不提前实施第三阶段。

## 4. 数据结构草案

| 结构 | 用途与约束 |
|---|---|
| study_profiles | owner_id主键；书斋名、门庭介绍、内斋介绍/札记、关闭拜帖及赠答开关、修订号与UTC时间。无记录时按私密默认值处理。 |
| study_visits | owner_id + visitor_id唯一；pending / accepted / declined / withdrawn / revoked，附言、状态时间、可重递时间、修订号。不是friends替代品。 |
| user_blocks | blocker_id + blocked_id联合主键、创建时间；禁止自屏蔽，检查双方记录。 |
| gifts（第二批） | ID、双方ID、小物枚举、附言、pending / accepted / declined、开放时间、幂等键；限定双方访问。 |

状态更新采用条件写入/事务与唯一约束；重复点击不重复授权、不重复赠送或通知。资料编辑使用修订号防覆盖。
旧用户、邀请、笔友和信件不回填为公开内容或访客授权。
无破坏性删列；小规模增量迁移不计划专门停机，但写事务可能短暂等待。
回滚应用时保留新增表；一旦启用屏蔽，不回退到绕过屏蔽的旧寄信代码，必要时关闭新入口并保留权限修补。

## 5. 必要验收与发布顺序

1. 对最终改动做一次类型检查及生产构建。
2. 检查匿名访客、主人、获准访客、无权用户、屏蔽用户的直接页面与接口访问；内斋不得进入公共缓存或搜索。
3. 检查拜帖重复递交、并发接见/婉谢、撤回访问、屏蔽对在途信件及通知的影响。
4. 第二批检查赠答幂等、拒收、限流及闭关。
5. 发布前沿用现有加密备份与增量迁移流程；不重复与本次无关的全站验证。
6. 第一批上线并交付后再接第二批；第二阶段结束时按需求书暂停，不提前开发唱和、雅集。

## 6. 旧图片缓存收尾

当前脚本支持按单一已迁移对象删除旧源并用R2 Head确认404；未见CDN purge实现。
不重跑永久删除来代替清缓存，也不对整个站点执行全量清缓存。
需要确定旧URL实际使用的域名及缓存服务：
- 若自定义域由Cloudflare缓存：仅对该旧URL及已确认的别名精确清理，需要相应zone的缓存清理权限；R2对象读写密钥不等于zone管理权限。
- 若使用其他域名/CDN：按实际服务精确失效；没有权限时记录缓存TTL与撤销状态。
- 不在公开仓库文档、更新日志或聊天中写出旧私人图片的完整地址。
本轮仅完成收尾路径梳理，未取得缓存清理成功证据。
